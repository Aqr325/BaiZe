# Red Team Ops Index

## 概述

按**真实行动顺序**组织的开源工具索引，覆盖 9 个阶段、400+ 项目。它的价值不是"列名字"，而是让 Agent 在授权测试的某个具体阶段，能快速回答一个问题：**这一步业界有哪些成熟工具、各自解决什么、哪些已被防守方重点检测**。

编排思路借鉴自公开红队资源清单（`JoasASantos/Awesome-Red-Team-Operations`）的"按攻击流程而非按工具类型"组织法；条目为本技能自行整理的索引，仅含工具名、一句话用途与官方链接，未搬运原文描述。

## 安全边界（硬约束）

- **仅限已授权**的安全测试（自有资产、书面授权的客户环境、CTF/靶场）。
- 本技能**只做索引**：不输出命令行参数、不构造载荷、不提供免杀/绕过的实现步骤。
- 用户描述的目标若无授权迹象（陌生域名、他人系统、要求"打进去"），明确拒绝并提示合规路径。
- 索引中出现某工具，**不等于推荐使用**——尤其涉及凭据窃取、横向移动的工具，仅在授权对抗演练与检测验证场景下有意义。

## 使用方式

**按阶段按需加载，不要一次读完**（全部约 400 条，整读会挤占上下文、也会掩盖当前阶段真正相关的十几条）。

| 阶段 | 章节文件 | 何时加载 |
|---|---|---|
| 1 侦察与资产测绘 | `01-recon.md` | 刚拿到目标、需要摸清攻击面时 |
| 2 Web 漏洞发现与利用 | `02-web-exploitation.md` | 目标是 Web 应用/API，需要按漏洞类型选工具时 |
| 3 执行与载荷 | `03-execution-payload.md` | 已获得执行点，需要处理脚本执行、载荷托管、回连时 |
| 4 持久化与提权 | `04-persistence-privesc.md` | 已落地低权限 shell，需要维持访问或提权时 |
| 5 凭据收集与外渗 | `05-credential-exfil.md` | 需要评估凭据暴露面、数据外带风险时 |
| 6 横向移动与 AD | `06-lateral-ad.md` | 目标是内网/域环境，需要评估横向路径时 |
| 7 C2 与基础设施 | `07-c2-infrastructure.md` | 需要理解指挥控制与基础设施搭建面时 |
| 8 对抗模拟与检测 | `08-adversary-emulation.md` | 做检测能力验证、紫队演练、恶意样本分析时 |

## 九阶段推进顺序

`侦察 → 初始访问 → 执行 → 持久化 → 提权 → 凭据收集 → 横向移动 → C2/外渗 → 对抗模拟`

这张顺序表本身就是导航：每拿到一个工具，先问一句**"它服务于第几步"**，清单立刻从一堆名字变成一张路线图。

## 操作原则

- **阶段优先**：先确定当前处于哪一步，再在本阶段章节里选工具，避免跨阶段乱抓。
- **检测视角配对**：选用任何工具前，同时看该章的"防守方视角"小节——知道它留下什么痕迹，才知道这次测试的结论该怎么写。
- **优先维护活跃的项目**：仓库长期停更的工具只能作历史参考，报告里不要当作当前有效风险证据。
- **结论落到证据**：工具只是手段，最终输出应是可复现的发现与修复建议，而不是工具使用记录。
